# Specification session

Read `CLAUDE.md`, `docs/README.md`, `docs/BUILD_SPEC.md`, `docs/PROGRESS.md`,
`docs/decisions.md`, and recent git history in that order. Define one coherent
change. Identify affected Part L invariants, RPC/public contracts, migration
risk tier, privacy/economy effects, acceptance criteria, and rollback. Update
the spec and add one ADR before implementation begins. Do not deploy, push,
change external settings, or treat review approval as implementation approval.

End with: files changed, exact decisions, unresolved questions, tests the
implementation must add, hosted actions still requiring separate approval, and
the exact candidate/base SHAs reviewed.
